# 前端设计与页面清单（阶段二 · v1.1 已落地）

> 状态：**方向 A 已选定并落地**；在原「暖陶 · 疗愈系」基础上扩展为**三主题系统**（陶瓷白默认 / 暖陶雅集 / 夜空黑），静态托管采用 `/` 根路径方案。Day2 v2 完成护工/医生/家属/管理员四页健康档案改造。
> 硬约束：原生 HTML+CSS+JS，无框架、无构建工具、无 npm；FastAPI StaticFiles 同端口托管；前端隐藏 ≠ 权限隔离（安全防线在后端，阶段一已实测）。

## 1. 美学方向（已选定：方向 A，扩展为三主题）

### 方向 A：「暖陶 · 疗愈系」（推荐）

贴合"康养陪伴"的情感定位，温暖但不甜腻。

- **配色**（CSS 变量统一管理）：
  - 主色 `--clay: #C4552D`（陶土暖橙，用于主按钮/当前态/品牌元素，克制使用）
  - 底色 `--paper: #F7F2E9`（米白宣纸底，大面积），卡面 `--card: #FFFDF8`
  - 点缀 `--moss: #5B7B5A`（苔绿，成功/在线态）、`--ink: #2E2A26`（墨色正文）
  - 锐利点缀 `--lacquer: #8A2E1F`（漆红，仅警示/删除确认）
  - 明确反对平均分配的 timid 调色板：陶土橙只出现在关键动作上，其余留白给米白与墨色。
- **字体**：标题「霞鹜文楷 / 楷体栈」（`LXGW WenKai, KaiTi, STKaiti, serif`——有手写体温，适老识别度高）；正文「思源宋体 / 宋体栈」（`Source Han Serif SC, Noto Serif SC, SimSun, serif`）。禁用 Inter/Roboto/Arial/system-ui 作标识字体。字体以**系统已装字体栈优先**，可选本地 woff2 子集增强（不依赖外网 CDN，保证内网可用）。
- **动效**：一次编排好的入场 stagger 渐显（页面载入时卡片自上而下 60ms 间隔浮现，CSS-only `@keyframes + animation-delay`），交互反馈只保留按钮按压 `scale(0.98)` 与 toast 滑入。无散乱微动效、无 hover 泛光。
- **形态**：大圆角卡片（14px）、粗描边分隔（1px `#E4DAC8`）代替阴影堆叠；像一本摊开的康养手册。

### 方向 B：「青瓷 · 专业护理系」

偏机构专业感，冷静可靠。

- **配色**：主色 `--celadon: #2F6D62`（青瓷绿）+ 底色暖灰纸 `#F4F3EF` + 点缀朱砂 `#B5442E`（警示）+ 藏蓝 `#2C3E50`（数据）。
- **字体**：标题「思源宋体粗宋」，正文系统黑体栈（`PingFang SC, Microsoft YaHei`）。
- **动效**：同方向 A 策略（克制、CSS-only）。
- **形态**：直角卡片 + 细分隔线，更像护理站工作屏。

两案共享同一套适老基线：**正文 ≥17px、行高 1.7、按钮点击区 ≥48px 高、对比度 ≥WCAG AA（4.5:1）、错误提示带图标不依赖颜色单通道**。适老化本身就是本产品的差异化卖点，直接写进视觉规范而非事后补丁。

### 1.1 三主题系统（Day2 v2 已落地）

全部颜色收敛为 CSS 变量，`css/main.css` 以 `:root` 承载默认主题，`html[data-theme="…"]` 整体切换，页面结构零改动：

| 主题 | 切换键 | 定位 | 关键色 |
| --- | --- | --- | --- |
| 陶瓷白（默认） | 移除 `data-theme`（`ceramic`） | 首要展示色：纯净白底不泛黄，注重文字清晰度 | 底 `#FFFFFF` + 白卡（描边+阴影分层） + 深墨正文 `#322E29` |
| 暖陶雅集 | `data-theme="terracotta"` | 原方向 A 配色完整保留 | 陶土橙 `#C4552D` + 米白 `#F7F2E9` |
| 夜空黑 | `data-theme="inknight"` | 深色环境/夜班使用，低亮度高对比 | 底 `#17181C` + 卡 `#202127` + 暖金点缀 `#D9A45B` + 米白文字 |

- **切换交互**：各页顶栏（KB.renderTopbar）右侧三枚色点（`.theme-dot`），点击即切、即时生效，当前主题色点高亮。
- **记忆**：`localStorage.kb_theme` 持久化；非法值回退陶瓷白。
- **无障碍不变**：三主题均满足正文 ≥17px、对比度 ≥WCAG AA；夜空黑正文用米白而非纯白，降低眩光。

## 2. 静态托管方案（已采用根路径）

**推荐：`/` 根路径直接托管**——访问 `http://127.0.0.1:8000/` 即登录首页，`/index.html`、`/admin.html`… 平铺；API 走 `/api/v1/*`、`/docs`、`/health` 均不冲突；`app/main.py` 挂载 `StaticFiles(directory=app/static, html=True)` 到 `/`，路由注册顺序保证 API 优先。
备选：挂 `/static` 前缀（首页在 `/static/index.html`，多一层路径，对长者入口不友好）。

### 3.1 index.html — 登录首页

- 顶部：品牌名「康伴」+ `/health` 状态角标（绿点=正常，红点+文字=异常）。
- 主体：**五块角色入口卡**（stagger 入场）：家属 / 老人 / 护工 / 管理员 / 医生。每卡角色名 + 一句说明 + 独立点缀色徽标。
  - 四个人账号角色：点卡展开行内登录表单（用户名+密码 → POST /auth/login → 存 sessionStorage → 按角色跳转对应页）。
  - **老人入口**：设备身份——`device_code + 设备 Token` 直接登录（Token 曾在注册时返回并保存的场景）；附带「一次性注册凭证换 Token」折叠入口（调 /auth/device/register，成功后保存 Token 并进入 elder.html）。
- 登录失败：行内错误（不 alert），保留 trace_id 供排障。
- 登出：各页右上角「退出」，清 sessionStorage 回首页。

### 3.7 debug.html — JWT 调试页（页头红字标注「仅限开发测试」）

- **取码区**：任意角色登录后跳到此页，自动展示 sessionStorage 中的 access_token（等宽字体块 + 一键复制），并解析 JWT payload 明文展示（sub/role/token_type/exp 本地 base64 解码，仅供人工核对）。
- **请求面板**：方法下拉（GET/POST/PUT/DELETE）+ 路径输入（默认 /api/v1/）+ 请求体 textarea + 「自动带 Authorization」开关 → 发送后展示状态码（大号着色：2xx 绿 / 4xx 红）+ 响应 JSON（格式化）+ 响应中的 trace_id。
- 用途：阶段二验收的越权实测（family 手调管理接口、伪造 Token、设备 Token 调人接口）都在此页操作留证。

## 4. js/api.js 统一封装

- `api(method, path, body)`：自动附 `Authorization: Bearer <token>`（人/设备 Token 同一存储槽，按页面角色注入）；非 2xx 抛出含 `detail + trace_id` 的统一错误对象。
- `openAuthorized(path)`（Day2 v2 新增）：带登录态打开下载/导出类页面——新标签页不自动携带 Authorization，直接 `window.open` 接口地址会 401，故先带 Bearer 取回内容再经 blob URL 打开（60 秒后回收）。
- `toast(msg, type)`、`confirmModal(text)`：原生实现，无依赖。
- 会话存取：`sessionStorage.setItem('kb_token'/'kb_role'/'kb_display_name')`，登出清空；角色不符直接回首页（前端引导层，安全由后端保证）。
- 主题存取：`localStorage.kb_theme`（ceramic/terracotta/inknight），KB.renderTopbar 渲染三色点切换器。
- 任何错误展示都带 trace_id 尾缀，方便与后端结构化日志对账。
