## 0. 文档头

### 0.1 编写目的

把散落在三份文档中的 POC 要求固化为一份可执行的验证计划：

- PRD《康伴3D数字人》第 9 章：POC-01～POC-11 的风险假设、最小验证、通过标准、计划阶段。
- TDD《康伴3D数字人》第 12 章：POC 到技术设计的门禁（验证产物与未通过处理）；第 13 章：10 项待 POC 确认的技术事项。
- ADR《康伴3D数字人》：ADR-007 / ADR-014 / ADR-015 处于"待验证"状态；各 ADR"备选方案"提供降级路线。

### 0.2 适用范围

- **Day1 只建框架，不执行任何 POC 实验**（不调 API、不下模型、不连外部服务）。
- 第一个实际执行的是 **Day3 的 POC-01/02**（WebRTC 回声与 ASR/TTS 流式体验）。
- 每个 POC 在其计划执行 Day 的**开工前**执行，当日回填结果；未执行不得开发依赖该决策的功能。

### 0.3 与三份文档的引用关系

| 文档 | 引用内容 | 本文档的处理方式 |
| --- | --- | --- |
| PRD 第 9 章 | POC 清单与通过标准 | 原文提炼，不修改 PRD |

### 0.4 门禁规则

- **POC 通过** → 对应 ADR 状态由"待验证"更新为"已接受"（走 ADR 变更流程）；同时锁定 TDD 依赖版本与 `.env` 真实配置。
- **POC 未通过** → 执行本文各节"失败降级方案"，不得宣称对应能力完成；PRD 第 10 章发布门禁第 8 条同样约束 POC-10/11。
- POC 结果**只回填本文档**，不回改 PRD/TDD 已发布版本。

## 2. 逐 POC 详述

### POC-01 WebRTC 语音回环

- **背景与风险假设**：产品需要低延迟全双工语音与口型同步，但教室网络不稳定（ADR-007"背景"；PRD §9 POC-01）。需要处理 STUN/TURN、异步事件循环、首包延迟与浏览器安全上下文（ADR-007"影响"）。
- **最小验证方法**（PRD §9）：平板→服务器→平板回声测试，跨机器连接并走指定 STUN/TURN。
- **量化通过标准**（PRD §9）：可听到回声；无持续报错；跨机器可连接。附：记录首包延迟作参考数据（TDD §12 要求"延迟记录"），本项不设延迟阈值——端到端承诺由 POC-08 承担。
- **失败降级方案**（ADR-007）：连接失败降级为文字聊天；TDD §12：保留文字降级，不进入端到端承诺。备选方案"HTTP 轮询"不采用。
- **计划执行 Day**：Day3。
- **结果记录栏**（执行后回填）：
  - 执行日期：2026-11-05（Day3 步骤 1，本地单机部分）
  - 实测数据：
    - 本地单机回声：通过——浏览器（Chrome，HUAWEI FreeClip 2 蓝牙耳机）采麦 → aiortc 回传 → 扬声器可听到自己语音，用户现场确认；
    - 服务端证据：`回传轨已挂接` → `连接状态: connected` → `首个音频帧到达服务端: pts=0 rate=48000 samples=960`（Opus 48kHz，20ms/帧）；
    - answer 生成耗时：约 5.0s（ICE 候选收集慢，Windows 多虚拟网卡主机现象；连接建立后媒体流正常，不影响体验结论，正式模块考虑预建 PC 或复用连接优化）；
    - 验证脚本：`scripts/poc01_webrtc_echo.py`（含首帧埋点与帧计数包装轨）。
  - 结论：**本地单机部分通过**。aiortc WebRTC 音频链路可用，满足"可听到回声、无持续报错"；两个实施教训已记录——① aiortc 的 `on("track")` 对 async 回调不等待，`addTrack` 必须在 `createAnswer()` 之前显式完成，否则 answer 方向为 recvonly；② `MediaStreamTrack` 无 "frame" 事件，帧诊断需用包装轨（见脚本文件头）。
  - 证据链接：`scripts/poc01_webrtc_echo.py`；运行日志（回传轨挂接/首帧到达记录，2026-11-05）。
  - **遗留项**：跨机器回声（走教师 STUN/TURN）待凭据提供后补测；`RTC_ICE_SERVERS` 已预留配置位。

### POC-02 ASR/TTS 流式体验

- **背景与风险假设**：流式 ASR/TTS 可能无法满足对话体验；厂商、协议、viseme 与超时阈值均未定（PRD §9 POC-02；TDD §13 第 4 项）。
- **最小验证方法**（PRD §9）：一句话转写并朗读，记录置信度和首包延迟。
- **量化通过标准**（PRD §9）：说话结束后 1 秒内出现转写；服务关闭时有可见降级。
- **失败降级方案**（TDD §12）：保留文字为主交互，不进入端到端承诺。
- **计划执行 Day**：Day3。
- **结果记录栏**：
  - 执行日期：2026-11-05（Day3）
  - 实测数据：
    - 环境：Docker `kangban-funasr`（funasr-runtime-sdk-online-cpu-0.1.13，2pass CPU），端口 10096→10095（自签名 TLS）；
    - 流式中间结果（2pass-online）：随说话实时输出，无丢句；
    - **说完→最终转写（2pass-offline）：242 ms**，达标（≤1s）；
    - 测试句"你好，康伴，今天房间温度怎么样。"实识"…康办…"（项目专名误识，可用 --hotword 热词修正，不影响判定）；
    - **Edge-TTS 首包延迟基线：1249 / 1331 ms**（两次实测，留作后续对照）。
  - 排障记录：该镜像 mode 值为 `2pass-online`/`2pass-offline`，客户端须模糊匹配（教师样板写法已实测确认）。
  - 结论：**通过**——转写延迟远优于 1s 门槛，TTS 可朗读且有首包基线；"服务关闭时可见降级"由应用层验收项 5 现场验证。
  - 证据链接：`scripts/poc02_funasr_asr.py`、`compose.funasr.yaml`。

### POC-04 声纹身份信号

- **背景与风险假设**：声纹误认会导致隐私泄露；双人间共用设备无法仅凭设备区分住户（PRD §9 POC-04；ADR-005"备选方案"）。阈值与声纹加密方案待定（TDD §13 第 3 项）。
- **最小验证方法**（PRD §9）：单/双人间注册、识别、低置信和服务关闭用例。
- **量化通过标准**（PRD §9）：单人间不被辅助声纹误阻断；双人间可主动确认；失败进入通用模式（不带个人记忆）。
- **失败降级方案**（TDD §12；ADR-005）：双人间强制主动确认或通用模式；声纹只作辅助身份信号，不作为唯一依据。
- **计划执行 Day**：Day4 / Day8（阈值与降级复核）。
- **结果记录栏**（部分回填，双人间链路提前至 Day3——见 Day3 规划 D2 决策）：
  - 执行日期：2026-11-05（Day3，双人间注册/识别/降级用例；单人间用例待 Day4）
  - 实测数据：
    - 环境：CAMPPlus（sherpa-onnx，192 维）+ TEN-VAD 服务端判定；向量入 `voiceprints` 表（pgvector），非文件方案；
    - **双人间主动确认**：设备（已连接·双人间）不能自行录入声纹（ADR-005 拦截，实测报错提示走管理员通道），改经 `POST /api/v1/voice/enroll/admin`（admin 凭证 + 指定 elder_id）录入成功；录入窗 5s + 秒级倒计时（3s 窗曾截断慢速朗读，已修复）；
    - **首句声纹验证**：阈值 0.55，三次实测相似度 **0.5652 / 0.6786 / 0.6044**，均 ≥0.55 通过并签发临时 Token（300s，仅内存）；
    - **免验机制**：有效期内连续 5 轮对话免验正常（"想不懂→今天天气很好→是的→嗯，没问题→你说的对"，每轮均触发模板回复 + TTS，用户现场确认）；
    - **失败降级**：无效语音/纯标点句不触发回复并如实提示"没听清"；声纹不通过进入通用模式（不带个人记忆）；录入后免重连生效（会话快照过期由 embedding_reloader 现场重查解决）。
  - 排障记录：实测曾出现"永远尚未录入"，根因是**设备绑定房间无长者**（声纹挂在另一房间长者上）——属数据配置问题而非代码缺陷，三方证据（psql 直查 + 服务端日志 + 前端状态）交叉定位解决；此教训印证"声纹跟随房间-长者关系"的门控设计有效。
  - 结论：**部分通过**。量化标准中"双人间可主动确认"与"失败进入通用模式"已实测满足；"单人间不被辅助声纹误阻断"未实测（当前验证设备均为双人间场景），与阈值 0.55 的误识/误阻复核一并留 Day4/Day8。
  - 证据链接：`app/services/voice.py`、`app/api/routes/voice.py`、`app/static/js/voice.js`（管理员通道面板）；用户实测截图（声纹验证通过·相似度 0.6044·连续 5 轮对话，2026-11-05）；`tests/test_voiceprint_service.py`（28 例语音测试全绿）。
  - **后续进展（同日晚）**：声纹验证复用扩展到登录页「老人生物识别进入」——`POST /voice/biometric/login` voiceprint 模式真比对同一 CAMPPlus 声纹库（同阈值 0.55），验证通过签发真实设备 JWT 进入长者页；实测冒烟通过（指纹模式签发 JWT 过 `/devices/me` 鉴权、无设备房 409、参数 422），9 例新测试覆盖（全量 136 passed）。该入口属教学演示后门（ADR-020，`BIOMETRIC_DEMO_ENABLED` 开关），不改变本 POC 的量化标准与 Day4/Day8 复核安排。
  - **后续进展（Day4，2026-11-06）**：单人间锁定 + 阈值 0.55 复核表 + 他人拒绝专项完成（详见 `Day_plan/Day4_验收报告.md` 验收项 7/8）：

## 3. 使用规则

1. 每个 Day 开工前先执行当日对应的 POC，**当日回填**"结果记录栏"四项（执行日期、实测数据、结论、证据链接）。
2. POC 结果只回填本文件；**不回改 PRD/TDD 已发布版本**；ADR-007/014/015 等状态更新单独走 ADR 变更流程（ADR"使用与变更规则"第 3 条：POC 可确认或推翻"待验证"决策，结果同步到 TDD、依赖、配置和测试）。
3. 通过的 POC 触发：对应 ADR 更新为"已接受" + 锁定 TDD 依赖版本 + `.env` 真实配置（密钥仍只经环境注入，不入 Git）。
4. 未通过的 POC 触发本文各节降级方案；对应能力不得在任何汇报、文档或代码注释中宣称"已完成"。
5. 实测数据必须可复算：保留原始命令、样例集版本与输出摘录作为证据。
