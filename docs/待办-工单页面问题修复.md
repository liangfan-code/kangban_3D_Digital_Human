## 一、问题清单

### 问题 1：医生端 / 护工端行内红点无法消除

**现象**：工单已「已处理」甚至已关闭，行首红点仍然存在；点击「查看」也不会消失。

**根因（两层）**

1. 红点判定过宽 —— `app/static/js/workorders.js` L238-L246：

   ```js
   var dot = it.is_read === false ? "<span class='wo-dot' title='本人未读'></span>" : "";
   ```

   只看本人是否有已读回执，**忽略 `my_status` 与工单状态**，所以 `handled` / `resolved` 的行也带红点。

2. 已关闭工单写不进回执 —— `app/services/workorder.py` L590-L602：

   ```python
   if workorder.status in CLOSED_STATUSES:
       raise WorkOrderConflict("工单已关闭，不可再变更")
   ```

   前端 `openDetail` 会调用 `POST /api/v1/staff/workorders/{id}/read`，命中 409 后被静默忽略
   （`workorders.js` L518-L521），回执始终不存在，红点永久保留。

**本地开发库实测（`kangban_dev`）**

| 角色 | 工单状态 | 处理项 | 无回执 / 总数 |
| --- | --- | --- | --- |
| doctor01 | cancelled | handled | 4 / 4 |
| doctor01 | resolved | handled | 2 / 3 |
| nurse01 | cancelled | unread | 2 / 2 |
| nurse01 | cancelled | read | 1 / 2 |
| nurse01 | resolved | handled | 2 / 3 |

共 6（医生）+ 5（护士）行「关闭但无回执」，与页面红点一一对应。

**补充**：顶部角标「工单 0」由 `count_open_by_role`（`workorder.py` L951-L985）统计
「未关闭 + 未处理 + 无本人回执」，口径正确；问题只在行内红点语义。

### 问题 2：搜索不支持长者姓名，且无「返回全部」入口

**后端**

`app/services/workorder.py` L897-L913 的关键词只做以下 ILIKE：

```python
Workorder.title / Workorder.sensitive_category / Workorder.description
/ 处理项 plan_text
```

未关联 `Elders.name`，因此搜「王跃进」必然 0 条；搜「跌倒」「急症」「长期用药」「测试药A」可命中。

**前端**

- `workorders.js` L697-L708：只有「搜索」按钮，没有清空 / 重置控件。
- `workorders.js` L248-L260：空结果只渲染「🍃 + 文案」，`state.q` 仍然保留；
  切换筛选或翻页都会继续带着关键词，只能手动删字再搜，体感是「回不去全部工单」。

### 问题 3：已取消工单对护士恒为「未读」

与问题 1 同源：

1. 取消工单时**没有同步处理项状态**（`workorder.py` L555-L570 只更新工单状态、`resolved_at`、事件）；
   护士的 `workorder_dispositions.status` 仍是 `unread`。
2. 前端无条件按 `my_status` 渲染状态标签（`workorders.js` L238-L246），于是显示「未读」。
3. `mark_read` 对关闭工单返回 409，回执写不进去 → 状态永远停在「未读」。

实测：`nurse01` 有 2 条 `cancelled + unread + 0 回执` 的工单。

       count(*) filter (where not exists (
         select 1 from workorder_reads r
         where r.workorder_id = w.workorder_id and r.account_id = a.account_id
       )) as no_receipt,
       count(*) as total
from workorders w
join workorder_dispositions d on d.workorder_id = w.workorder_id
