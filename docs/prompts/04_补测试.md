# 模板 04：补测试

> 用途：为已有实现补测试。本项目强制要求：**写操作必须回查数据库**，禁止只断言 HTTP 200。

## 模板正文

```
【Context 背景】
项目：康伴 3D 数字人康养陪伴系统。
被测对象：{文件/接口清单}。
测试基建：{测试库 / fixture / 现有 conftest 能力}。
覆盖依据：{测试设计章节，如 Day2 文档 6.4 节}。

【Task 任务】
编写测试覆盖以下场景：{逐条列出场景与预期状态码/副作用}。

【Constraints 约束】
- 所有写操作断言"HTTP 状态 + 回查数据库"双验证，禁止只断言 200；
- 测试数据只进测试库（kangban_test），严禁写 kangban_dev；
- 认证类测试必须覆盖：错误凭证统一 401 不泄露差异、过期/伪造/吊销凭证 401、
  越权 403/404 语义（存在性隐藏用 404，无权限角色用 403）；
- 不 mock 数据库行为本身，走真实 PostgreSQL 事务回滚隔离；
- 测试命名与文件组织遵循现有 tests/ 结构。

【Expected Result 预期结果】
新增测试文件清单 + 每个文件覆盖场景表；`python -m pytest` 实测输出
（通过数/失败数），失败项修复后复测的完整记录。
```

## 本项目示例

```
【Context 背景】
项目：康伴 3D 数字人康养陪伴系统，Day2 身份与权限已实现。
被测对象：POST /api/v1/auth/login、GET /api/v1/auth/me（人/设备双身份）。
测试基建：conftest 连 kangban_test，session 级 alembic upgrade head，函数级事务回滚，
种子 fixture 提供四角色账号。
覆盖依据：《Day_plan/Day2_3D康伴数字人.md》6.4 节 test_auth_login.py 行。

【Task 任务】
编写 test_auth_login.py：四角色正常登录 200；错误密码 401（响应不区分"用户不存在/密码错误"）；
禁用账号 401；伪造/过期 JWT 401；/auth/me 解出正确角色；人 Token 调设备接口 403。

【Constraints 约束】
- 登录成功断言响应含 role 且回查 accounts.last_login 相关字段（如设计有）；
- 伪造 Token 用篡改签名与篡改 payload 两种方式构造；
- 只写 kangban_test。

【Expected Result 预期结果】
tests/test_auth_login.py；python -m pytest tests/test_auth_login.py 全绿并给出实测输出。
```
