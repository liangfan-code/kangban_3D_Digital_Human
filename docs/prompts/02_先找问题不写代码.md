# 模板 02：先找问题，不写代码

> 用途：评审已有设计/代码/迁移/文档时，让 AI 只输出问题清单，**禁止顺手修复**。

## 模板正文

```
【Context 背景】
项目：康伴 3D 数字人康养陪伴系统。
评审对象：{文件路径 / diff / 设计章节}。
该对象的预期目标与依据：{PRD/TDD/ADR 对应章节}。

【Task 任务】
只评审，不修改。请找出：
1. 正确性问题（逻辑错误、边界遗漏、并发/事务问题）；
2. 安全问题（身份绕过、信息泄露、注入、敏感数据落日志）；
3. 与依据文档不一致之处（逐条对照）；
4. 可维护性问题（命名、职责、重复代码）——单独列，不与前两类混淆。

【Constraints 约束】
- 严禁修改任何文件、严禁给出"我已经修好"的表述；
- 每个问题必须给出：位置（文件:行号 或 章节）、严重级别（阻断/高/中/低）、依据；
- 不确定的问题标注"待验证"，不得编造。

【Expected Result 预期结果】
输出问题表：编号 | 位置 | 类别 | 严重级别 | 问题描述 | 依据/建议。
无问题的类别明确写"未发现"，不凑数。
```

## 本项目示例

```
【Context 背景】
项目：康伴 3D 数字人康养陪伴系统。
评审对象：alembic/versions/0003_accounts_device_tokens.py（全文见附件/文件）。
预期目标：《Day_plan/Day2_3D康伴数字人.md》第 5.1/5.2 节表结构设计。

【Task 任务】
只评审该迁移文件：字段类型、CHECK 约束、唯一约束、索引、外键删除策略、
downgrade 完整性是否与设计一致；找出遗漏与错误。

【Constraints 约束】
- 严禁修改文件、严禁执行 alembic 命令；
- 每条问题给出位置与严重级别；
- 与设计文档不一致处逐条对照列出。

【Expected Result 预期结果】
问题表（编号|位置|类别|严重级别|描述|依据），末尾给出"是否可执行 upgrade"的明确结论。
```
