# 提示词模板库 v1（Day2）

> 定位：本项目 AI 协作的标准提示词模板。所有模板遵循统一四要素结构，
> 目标是让 AI 输出可审查、可验证、不越范围。

## 四要素结构

每个模板由四部分组成，缺一不可：

| 要素 | 回答的问题 | 常见缺失后果 |
| --- | --- | --- |
| **Context（背景）** | AI 需要知道哪些项目事实、已有约定、前置依赖 | 输出与项目现状脱节，编造不存在的接口/表 |
| **Task（任务）** | 本次要做什么，产出物是什么 | 输出泛泛而谈，或顺手做了没让做的事 |
| **Constraints（约束）** | 红线、范围边界、禁止事项、技术选型限制 | 越权改动、违反安全禁区、引入未选型依赖 |
| **Expected Result（预期结果）** | 什么算完成，如何验证，输出格式 | "看起来做了"但无法验收，幻觉测试 |

## 七条好提示词标准

1. 背景给足：引用具体文档章节/文件路径，不让 AI 猜项目状态。
2. 任务单一：一次一个任务，不混合"设计 + 实现 + 测试"。
3. 约束显式：安全禁区、范围排除项逐条写出，不依赖 AI 自觉。
4. 验收可测：预期结果必须是可执行的命令或可观察的输出。
5. 明确"不做什么"：排除项与包含项同等重要。
6. 要求汇报格式：约定输出结构（如表格、diff、文件全文），便于人审。
7. 声明歧义处理方式："有不明白先提问，不得先斩后奏"。

## 提示缓存注意事项

- 多轮对话中**固定前缀保持逐字节稳定**（项目背景段不要每次改写），才能命中提示缓存、省钱提速。
- 变化的信息（本次任务、报错日志）放在提示词**末尾**，固定的 Context/Constraints 放**开头**。
- 长文档引用优先给"文件路径 + 章节号"，由 AI 按需读取，避免每次全文粘贴导致前缀漂移。

## 人工任务（不由 AI 代做）
