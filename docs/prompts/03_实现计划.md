# 模板 03：实现计划

> 用途：中大型改动开工前，让 AI 产出分步计划与风险清单，**确认后再执行**。

## 模板正文

```
【Context 背景】
项目：康伴 3D 数字人康养陪伴系统。
当前状态：{已完成能力 + 关键文件/迁移版本}。
目标依据：{需求文档章节}。

【Task 任务】
制定实施计划，不写实现代码：
1. 拆分步骤（每步：产出物、涉及文件、依赖关系）；
2. 标注每步的验证方法（可执行命令）；
3. 列出风险点与回退方式；
4. 指出计划中需要人工审查/确认的检查点。

【Constraints 约束】
- 不得超出目标依据的范围（明确列出本次不做的事项）；
- 遵守项目安全禁区（不连生产库、不提交密钥、不 push 等）；
- 高风险文件（auth/迁移/工具权限）必须设人工审查检查点；
- 步骤粒度以"每步可独立验证"为准。

【Expected Result 预期结果】
输出：步骤表（序号|产出物|涉及文件|验证命令）+ 风险清单 + 人工检查点清单。
我确认计划后才进入执行。
```

## 本项目示例

```
【Context 背景】
项目：康伴 3D 数字人康养陪伴系统。
当前状态：Day1 骨架完成（11 表、0001/0002 迁移、11 测试全绿）。
目标依据：《Day_plan/Day2_3D康伴数字人.md》第 8 章 11 步。

【Task 任务】
制定 Day2 身份与权限模块实施计划：依赖配置、提示词模板库、6 张新表 ORM 与迁移 0003/0004、
auth 模块（passwords/jwt/device_token/dependencies）、schemas+services、路由、seed_admin、
测试改造与攻击用例、POC-05 回填。

【Constraints 约束】
- 只做 Day2 范围；Day3+（WebRTC/ASR/会话/声纹/System One 等）一律不做；
- 新表仅限 6 张；不回改 0001/0002；
- 迁移与 auth 每个文件人工审查后才继续；
- pytest 只连 kangban_test；全程本地提交，严禁 push。

【Expected Result 预期结果】
11 步实施表（每步含验证命令）+ 风险清单 + 4 个人工检查点（迁移人审、auth 逐文件人审、
范围冻结、验收确认）。
```
